# Central window decorations

MiracleOS builds a small, version-pinned fork of Debian Sway 1.10.1. The compositor renders the title bar and routes its controls to the actual window container. This avoids global layer-shell overlays intercepting clicks over unrelated windows.

The patch adds close, scratchpad minimize and floating maximize/restore controls. Maximize uses the workspace's usable area and keeps the title bar; fullscreen continues to hide decorations. Each window owns its restore geometry. Existing compositor title-bar dragging and border resizing remain in place. Colors use Sway `client.*` configuration, generated by the desktop theme.

Version 2 renders the header with a compositor-owned Cairo scene buffer: separate rounded title and control tabs, a transparent middle, concave joins and an accent close pill. Controls use icons only at every width, with three 38-pixel hit areas in a compact 114-pixel tab. Background and text follow `client.*`; the close accent follows its `indicator` field. With at least 6 pixels of frame padding, an additional cached Cairo border supplies 16-pixel outer bottom corners while leaving every client pixel intact. Client content retains its own square or rounded interior shape. There is no extra compositor blur or exterior shadow.

Wayland clients supporting the decoration protocol are asked to use server decorations. Other clients, including Xwayland programs with their own title bar, receive an outer compositor header. Arbitrary client-drawn controls cannot safely be removed by the compositor; no app pixels are cropped. MiracleOS clients omit their own header when `MIRACLEOS_SERVER_DECORATIONS=1`.

Build on Debian with the matching source and development dependencies:

```sh
sudo apt-get build-dep sway
apt-get source sway=1.10.1-2
./compositor/build.sh ./sway-1.10.1
sudo ./compositor/install.sh ./sway-1.10.1/build-miracleos/sway/sway
```

`build.sh` expects pristine upstream source, and fails when patch anchors differ. The installer retains the original session script for rollback and never overwrites `/usr/bin/sway`. The root-owned login greeter remains on stock Sway. A logout/login or VM restart is required to activate a new compositor binary. Revert by restoring `/usr/local/bin/miracleos-session.before-central-frames` over the session script, then log in again.

Release packaging should include the patched compositor and its source patch under the same versioned release as the desktop/runtime. The Sway binary requires the matching Debian wlroots 0.18 ABI. Build and integration tests must run before distributing an update; hot replacing a running compositor is unsupported.

For each distributed compositor binary, include its corresponding upstream Sway 1.10.1 source archive, this exact patch script, `miracleos-header.h`, build instructions and upstream license notices in the same release's source archive. A link to a moving upstream branch is insufficient to reproduce the distributed binary. The binary version includes `-miracleos.2` to distinguish it from stock Sway.

`check-headless.py` starts a separate headless compositor socket and tests actual pointer clicks for Xwayland and GTK Wayland CSD windows, fullscreen, narrow-window fallback and maximize/minimize/close round trips. It also captures a themed native preview with `grim`; the real desktop socket is never targeted.

The v2 header follows the supplied two-tab design: title and app glyph on the left, icon-only minimize/maximize/close controls on the right, transparent space between them and an accent close pill. The control tab stays compact at all window widths. The floating header is painted natively with Cairo; client content is retained without cropping. Its palette is generated from the system accent and light/dark setting.
